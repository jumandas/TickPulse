# TickPulse

A real-time market data dashboard, built as a portfolio project in the exact stack used for modern backend and full-stack roles: ASP.NET Core, SignalR, PostgreSQL, Redis, and Angular.

TickPulse streams live price ticks to the browser, stores tick history, and runs a small AI market analyst that watches the feed and explains unusual events in plain English.

## What it shows

- Live tick table with prices updating in real time over SignalR
- Price chart per symbol, fed by the history API
- Watchlist with add and remove
- Connection status for the live feed
- Analyst feed: every time the market does something odd, a short explanation appears, with a label showing whether it came from the rule-based analyst or the OpenAI analyst

## All market data is synthetic

Every price is generated by a random walk in the backend. The tickers are invented (ACME, GLOB, NOVA, ORBT, PULS, QNTM, VTX, ZENX) and none of them map to a real company. There is no real market data anywhere in this project, and nothing here is based on proprietary work.

## Architecture

```
Angular frontend (Signals, SignalR client)
        |  REST + SignalR
ASP.NET Core Web API
  TickEngineService (BackgroundService)
    generates synthetic ticks every 250 ms
    > in-memory latest quotes
    > Redis pub/sub + cached quotes
    > SignalR hub
    > Postgres (batched tick history)
    > channel to the analyst worker
  AnalystWorker (BackgroundService)
    detects anomalies, asks the analyst for an explanation,
    stores the event, pushes it to SignalR
  TickPulse.Core (tick generator, anomaly detection)
  TickPulse.Analyst (rule-based analyst, OpenAI analyst)
        |
PostgreSQL (tick history, symbols, watchlist, analyst events)
Redis (pub/sub fan-out, quote cache)
```

The analyst module is deliberately small and separate. It is one interface, `IMarketAnalyst`, with two implementations: a rule-based analyst that always works, and an OpenAI analyst that is used only when an API key is configured. If the OpenAI call fails, the worker falls back to the rule-based analyst so the feed never stops.

## How to run

### With Docker (recommended)

```bash
docker compose up --build
```

- API at http://localhost:5000 (Swagger at /swagger)
- Frontend at http://localhost:4200

### Without Docker

You need .NET 8 SDK, Node 20 or newer, PostgreSQL, and Redis running locally.

```bash
# Backend
cd src/TickPulse.Api
dotnet run
# API listens on http://localhost:5000

# Frontend (in a second terminal)
cd frontend
npm install
npm start
# App listens on http://localhost:4200
```

The API works without Postgres and Redis, but history and watchlists need Postgres, and Redis publishing is skipped with a warning when Redis is down. The live feed itself keeps working from memory.

### With the OpenAI analyst

```bash
export OPENAI_API_KEY=sk-your-key-here
docker compose up --build
```

Without the key, the app uses the built-in rule-based analyst. The key is read from the environment only and is never written to a file in this repo.

## API

- `GET /api/symbols` - all synthetic symbols
- `GET /api/quotes` - latest quote per symbol
- `GET /api/quotes/{ticker}` - latest quote for one symbol
- `GET /api/history/{ticker}?minutes=60&limit=500` - tick history
- `GET /api/watchlist`, `POST /api/watchlist`, `DELETE /api/watchlist/{ticker}` - watchlist
- `GET /api/analyst/status` - which analyst is active
- `GET /api/analyst/events?limit=20` - recent analyst events
- SignalR hub at `/hubs/market` - send `SubscribeAll` or `Subscribe(ticker)`, receive `Tick` and `AnalystEvent` messages

## Tests

```bash
dotnet test tests/TickPulse.Tests/TickPulse.Tests.csproj
```

Tests cover the tick generator, anomaly detection, the rule-based analyst, and the API endpoints (hosted in memory with an in-memory database).
